Lab 01

SQL Injection

登入系統把使用者輸入直接拼進 SQL 查詢字串，攻擊者可藉此繞過登入驗證，並進一步新增、竄改或刪除資料庫內容。

嚴重度 High   模擬登入 + 資料表

漏洞原理

登入時伺服器組出的查詢語法如下，使用者輸入被當成查詢條件的一部分：

有漏洞的查詢
SELECT * FROM users WHERE username = '<輸入>' AND password = '<輸入>'

靶機以 executescript() 執行查詢，允許一次執行多條以分號 ; 分隔的 SQL。因此攻擊者不只能繞過登入，還能接著執行 INSERT、UPDATE、DELETE。

登入成功後，系統會把整張使用者資料表顯示出來，方便對照注入前後的變化。

正常示範帳密：ADMIN / admin001。注入 payload 貼到帳號欄，密碼可留白。

防禦修補

根本做法是採用參數化查詢（prepared statement），把使用者輸入當成純資料綁定，而非以字串拼接組成 SQL。輸入即使含有引號或分號，也只會被當成字串，不會改變語法結構。

正確寫法
cursor.execute(
    "INSERT INTO users (username, password, isAdmin) VALUES (?, ?, ?)",
    (username, password, is_admin),
)
